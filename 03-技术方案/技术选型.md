# 技术选型方案

## 一、推荐方案对比

### 方案A：纯MaxKB搭建（推荐，适合快速出作品）
| 层 | 技术 | 说明 |
|---|---|---|
| 智能体平台 | 飞致云MaxKB | RAG知识库、工作流编排、多模型接入 |
| 前端 | MaxKB内置应用界面 + 嵌入页面 | 或自写简单HTML/JS嵌入 |
| 后端 | MaxKB API + Python脚本 | Python处理PPT生成、Excel导出等 |
| 知识库 | MaxKB内置(PgVector) | 上传文档自动分段+向量化 |
| 模型 | 学校提供的免费Token模型 | 国内主流大模型 |
| 部署 | MaxKB应用链接分享 + Docker | 支持密码保护分享 |

**优点**：开发快、已培训、低代码、适合比赛时间
**缺点**：灵活性有限、PPT生成等需外挂Python

### 方案B：MaxKB + 自研前端
| 层 | 技术 | 说明 |
|---|---|---|
| 智能体平台 | MaxKB（知识库+对话+工作流） | 负责AI核心能力 |
| 前端 | Vue3 + Naive UI 或 React + Ant Design | 自研学生/教师双端界面 |
| 后端 | Python FastAPI | 业务逻辑、PPT生成、数据处理 |
| 知识库 | MaxKB API调用 | 通过MaxKB API进行检索 |
| 部署 | 前端静态部署 + 后端容器化 | 需要服务器 |

**优点**：界面灵活、功能完整
**缺点**：开发量大、需要前后端能力

### 方案C：纯代码开发
| 层 | 技术 | 说明 |
|---|---|---|
| AI框架 | LangChain / LlamaIndex | 自建RAG流程 |
| 前端 | Vue3 / React | 完全自研 |
| 后端 | Python FastAPI | 全栈自研 |
| 向量库 | ChromaDB / Milvus | 自建知识库 |
| 模型 | 学校Model API | 调用大模型 |

**优点**：完全可控、创新性强
**缺点**：工作量大、重复造轮子

---

## 二、推荐选择：方案A + 轻量前端优化

**理由**：
1. 比赛培训已讲MaxKB，上手最快
2. P0核心功能MaxKB都能覆盖（知识库、对话、组卷、判卷、授课计划）
3. 仅PPT生成、数据导出等需要额外Python脚本 → MaxKB支持自定义Python工具
4. 时间优势：7月底开始，9月底提交，方案A更可能做出完整作品

**轻量前端优化**：
- 若纯MaxKB内置界面不够美观 → 写一个简单的HTML页面嵌入MaxKB应用（iframe或API调用）
- 使用MaxKB的"公开访问链接+密码保护"即可完成"学生端/教师端"的分离展示

## 四、关键技术难点与解决方案

| 难点 | 解决方案 |
|---|---|
| PPT生成 | MaxKB自定义Python工具调用python-pptx库 |
| 题库结构化存储 | 使用MaxKB知识库分段+自定义标签区分题目 |
| 多轮对话上下文 | MaxKB历史聊天记录变量+意图识别工作流 |
| 双端数据隔离 | 利用MaxKB多应用 + "对话用户"机制区分师生 |
| 数学公式渲染 | 前端引入KaTeX/MathJax，Markdown渲染 |
| 学情数据分析 | 通过表单收集测试结果 → Python脚本统计 → 可视化 |
