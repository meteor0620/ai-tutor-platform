# 用户角色分析

## 一、角色定义

### 1. 学生
- **身份**：全日制在校本科生/研究生
- **核心需求**：高效掌握课程知识、自测水平、查漏补缺
- **痛点**：
  - 课后缺乏即时答疑渠道（老师不可能24小时在线）
  - 不知道自己薄弱点在哪，复习没有针对性
  - 传统刷题效率低，不会的题看完答案还是不懂
- **使用频率**：每周2-4次，考试前高频

### 2. 教师
- **身份**：课程主讲教师/助教
- **核心需求**：减轻备课组卷负担、掌握班级学情、提升教学效果
- **痛点**：
  - 出卷耗时（选题、排版、配分）
  - 授课计划编写繁琐，每次开课都要重新调整
  - PPT制作占用大量时间
  - 无法实时了解每个学生的掌握情况
- **使用频率**：每周1-3次

### 3. 管理员（可选P2）
- **身份**：教务处/学院管理员
- **核心需求**：课程数据汇总、平台运营
- **暂不纳入比赛范围**

---

## 二、核心用户旅程

### 学生端典型场景

```
打开课程 → 看老师本周授课计划 → 勾选要学的单元 
→ 浏览知识库学习知识点 → AI讲解不懂的地方 
→ 生成一套自测题 → 作答提交 → 查看分数+逐题解析 
→ 错题自动归入错题本 → 下次重点复习错题
```

### 教师端典型场景

```
创建课程 → 上传教材/课件构建知识库 
→ AI生成授课计划 → 手动微调后发布 
→ 按章节AI生成PPT → 下载使用 
→ 阶段测试前AI智能组卷 → 发布测试 
→ 查看学情看板 → 调整后续教学重点
```

## 三、双端数据流关系

```
教师端                          学生端
┌──────────┐                   ┌──────────┐
│ 知识库    │──── 同步 ────────→│ 知识库    │
│ 题库      │──── 同步 ────────→│ 题库      │
│ 授课计划  │──── 同步 ────────→│ 单元选择  │
│ 测试/作业 │──── 发布 ────────→│ 在线作答  │
│ 学情看板  │←── 反馈 ─────────│ 测试结果  │
│          │                   │ 错题数据  │
└──────────┘                   └──────────┘
```
