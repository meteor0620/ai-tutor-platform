## 一、项目定位

面向高校课程教学的 **双端AI智能教辅平台**,覆盖学生"学-练-测-问"和教师"备-教-批-管"全流程：

| 端 | 核心能力 |
|---|---|
| **学生端** | 知识库检索·AI逐题讲解·智能组卷自测·多轮答疑·错题本 |
| **教师端** | 知识库管理·智能组卷·学情看板·(备选)AI授课计划·(备选)AI生成PPT |

## 三、技术架构(方案B,已实际采用)

> 历史文档 `03-技术方案/技术选型.md` 推荐"方案A纯MaxKB",**实际开发已演进为方案B**(MaxKB为AI核心 + 自研FastAPI/Vue3做组卷判卷与界面亮点),不再回头。此决策为本次方案修订的核心变更。

```
门户 Vue3 (:5173) ── vite proxy ──┬── /chat, /admin → MaxKB (:8080)   [AI对话/知识库/工作流]
                                  └── /api          → FastAPI (:8001)  [题库/组卷/判卷/错题/学情/知识库代理]

MaxKB (Docker, v2.10.4-lts, 端口8081)：
  ├── 模型: DeepSeek (LLM) + maxkb-embedding (本地向量)
  ├── 知识库: AI教辅智学平台(307段) / 高等数学(287段) / 大学英语(15段)
  ├── 应用: AI微积分助教 / AI英语助教(SIMPLE) + [待建]平台助手 / 学情分析
  └── 工作流: [待建]平台助手智能RAG、学情分析

FastAPI 后端 (:8001, SQLite aiplatform.db)：
  ├── questions.py   题库(手动录入 + DeepSeek批量生成,高数81题/英语15题)
  ├── papers.py      智能组卷/在线作答/自动判卷/错题本
  ├── knowledge.py   知识库代理(浏览/检索,内部持 admin token)
  └── database.py    SQLite(aiplatform.db)
```

**职责边界(约定)**
- **MaxKB 管**：知识库、RAG对话、智能体工作流(平台助手/学情/未来教师端AI)
- **FastAPI 管**：结构化数据与业务逻辑(题库、组卷、判卷、错题、学情统计)、知识库代理
- **门户管**：学生端+教师端界面(复用同一套 Vue3)
